# 配置模块开发

领域模块位于 `src/core/modules/`，不依赖 React、浏览器文件句柄或网络。编译期在 `index.ts` 注册 `ConfigModule`，界面在 `src/modules/ui.tsx` 独立注册。工程中的模块声明只包含数据，不加载或执行工程附带的脚本。

`contracts.ts` 是实际接口定义。`syntax` 控制源码编辑器的语言展示；应用源码草稿时始终调用模块解析器，不仅检查文件扩展名。每个模块提供：

| 接口 | 职责 |
| --- | --- |
| `id` / `version` / `role` | 标识模块契约及文件用途；模块版本与应用版本分开维护 |
| `capabilities` | 声明只读、可创建、高级编辑及桌面能力需求 |
| `detect(file)` | 对普通文件导入进行识别；多模块同时匹配时报告用途冲突 |
| `parse(file)` | 解析源文档；失败可保留原文件，不阻止工程存档 |
| `validate(value, context)` | 返回语义诊断；当前运行导出只检查活动文件及其依赖 |
| `references(value, context)` | 返回资源字段及原路径；统一层解析工程映射、目录和外部依赖 |
| `export(value, context)` | 接收统一层分配的路径与引用改写，输出文件字节；统一层检查路径冲突、工具元数据隔离及 ENI 字节不变 |

导出器不得修改输入工程。没有改动时优先返回源字节；YAML 需要改写时使用文档 AST，避免覆盖注释和未知字段。模块导出结果必须包含计划内的源文件路径，可以附带其他输出，但不能覆盖另一输出或写入 `project-data/`。跨模块字段校验与主站信号目录仍由项目校验层协调。

新增模块通常只需新增领域实现、在领域注册表注册，并按需在 UI 注册表提供标题、编辑器及创建/关联动作。导入、引用收集、归档与运行导出调用统一接口。模块依赖的资源不能通过模块自行下载，也不能依赖网页访问任意本地路径。

## 工程声明与兼容

`ModuleSnapshot` 保存在 manifest 的 `modules`，同一模块可通过不同 `instanceId` 形成多个实例：

- `id`、`version`：对应已编译模块及准确契约版本。
- `fileIds`：拥有的配置/资源文件；`stateFileIds`：工具状态文件，禁止进入运行包。
- `required`：恢复工程必需。缺少该模块或版本时只提供摘要与原包复制。
- `requiredForRuntime`：运行必需，默认将该模块的配置文件作为运行根。
- `runtimeFileIds`：显式运行根文件子集，必须属于本实例。
- `dependsOn`：依赖的实例 ID；没有 `instanceId` 的旧声明按模块 ID 标识。

依赖图与文件引用共同决定运行闭包。缺少依赖、活动依赖环、未知活动模块及 Web 中需要桌面能力的模块会产生阻塞诊断。普通文件引用形成的资源环通过去重收集；它不等同于模块派生任务环。

已支持容器中的未知可选模块保留文件字节、工具状态、声明中的额外字段、原引用，以及文件索引的额外元数据。界面和领域写入入口保持只读。未知模块可以留在工程中；它成为运行根或被活动配置引用时必须阻止运行导出，不能当作普通附件绕过校验。

较新容器/工程 schema、未知必需模块或无法解释的核心入口只提供 ZIP 摘要和原包复制。未知容器版本不宣称已通过其 manifest 契约校验。普通编辑接口不会得到这个包的可写工程。当前没有历史版本迁移适配器。受支持格式的损坏归档可显式检查并创建独立恢复工程；不完整模块的原文只读隔离，仍需适配器和完整数据才能恢复可编辑能力，详见 [工程恢复](RECOVERY.md)。

`createdWith` 保留首次创建应用信息，`lastSavedWith` 记录本次保存应用信息。现有 v1 归档中按角色分组且没有 `instanceId` 的声明仍可读取；新实例使用稳定文件 ID 派生标识。未知角色名不会被改写为附件。

## 内置示例：末端负载

`app.payload` v1 对应本机 `rocos-app` 提交 `7093bcd` 的 `Robot::LoadLoadParameters` / `SetLoadParameters`（`src/robot.cpp`）：

```yaml
mass: 0.0       # kg；0 表示没有末端负载
com: [0, 0, 0]  # m；省略时使用法兰原点
```

质量必须为有限非负数。`com` 若存在，消费端要求至少三个元素并读取前三个；额外元素和未知字段保留并提示。编辑器只提供质量和前三个质心坐标。每个负载文件独立编辑，创建操作通过 AST 更新 APP 的 `robot.payload` 相对路径，旧文件仍留在工程中。未关联的负载文件不会自动进入运行包。

这里的校验依据是已核对的消费端源码，不代表已运行真实负载辨识或控制器。切换到未经核对的 APP 目标版本会阻止该模块运行导出。

## 验证

`tests/modules.test.ts` 用独立注册的测试模块验证识别、解析、语义诊断、依赖收集、导出改写及归档重开，无需修改主流程。它还覆盖未知模块保留、版本只读处理、重复所有权、依赖环、桌面能力及 ENI 不变约束。`tests/browser/modules.spec.ts` 验证负载 UI、实际下载文件与新会话重开、未知模块只读和原包复制。
