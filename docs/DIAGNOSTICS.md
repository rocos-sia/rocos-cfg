# 诊断定位

在“校验与导出”中运行校验后，每条诊断显示规则、文件及字段/对象路径。“定位”跳转并聚焦相应位置；有文件来源的警告也可定位。没有文件来源的全局检查不提供虚构的字段目标。

- 主站和 APP 启动字段进入现有表单；IgH PDO/SDO 会切换到编辑标签并选中相应从站。
- Hardware 使用 YAML 中的条目序号选择设备，再聚焦信号、机械参数或确认控件。条目序号与设备 ID 不混用。
- 文件/目录引用进入 APP 的资源映射表；目标不在当前分页时自动显示对应页。
- 不支持表单编辑的字段、文件级或语法错误进入源码视图。ENI 保持只读，ECM 启动 YAML 与 ENI 的诊断来源分开记录。
- 标准 URDF Joint、Link 问题保留实际 XML 序号，可定位到对应源码对象；旧 `<hardware>` 不参与语义定位。原模型树自身的“定位到 URDF 源码”入口保持不变。

“返回诊断结果”保留校验结果；源码视图另有“返回配置页面”。定位属于视图操作，不修改配置、不新增撤销步骤、不写入工程文件。聚焦和离开超出范围的原始数值也不会自动将其夹紧成合法值，必须由用户明确修正。

## 过期结果与草稿

诊断绑定工程 UUID、工作区会话和 revision。修改工程或替换同 UUID、同 revision 的另一份快照后，旧结果标为过期，“定位”禁用，须重新校验。

目标文件有未应用草稿时，直接打开原草稿并显示提示；不把已应用配置中的偏移套到可能已改变的草稿。源码视图在继续输入、异步保存草稿和应用时保持挂载，诊断过期不会中断输入或重置光标。切换语言、主题也不会重复抢焦点。

YAML 按 AST 路径定位，区分列表中重复的字段；缺少目标字段时停在最近可定位的父节点，遇到 alias 停在引用自身。语法错误使用解析器的错误范围。XML 按直接子节点和文件内序号定位，跳过注释、CDATA 中的伪标签，并兼容命名空间与换行；无可靠字段位置时仅打开源文件，不声称精确定位。

## 验证入口

```sh
npm test -- tests/diagnostic-location.test.ts
npm run test:ui -- tests/browser/diagnostic-location.spec.ts --workers=1
```

Chrome 用例覆盖键盘聚焦、非顺序设备 ID、PDO/SDO、ECM 字段与只读 ENI、无效源码草稿、异步草稿编辑/应用、资源分页、同 UUID 快照替换，以及窄窗下主站、Hardware、APP 与诊断表的可用性。完整执行结果按版本记录在 [BUILD-VERIFICATION.md](BUILD-VERIFICATION.md)。
