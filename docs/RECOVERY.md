# 工程恢复

正常打开始终使用严格检查。ZIP、索引、SHA-256 或编辑状态检查失败时，不会自动放宽检查并进入编辑，而是展示失败原因，保留当前工作区。界面提供原包复制、检查可恢复文件和创建恢复工程三个独立操作。

## 检查与提取

恢复检查使用与正常导入相同的路径、文件数量、单项大小和累计解压限额。完整中央目录中的条目按声明边界逐项读取，分别校验 CRC。单个文件解压失败或 CRC 不一致不会使其他文件被当作有效文件；该条目列为损坏。

若中央目录或结束记录被截断，恢复器从完整本地头开始按明确长度顺序读取，不搜索并猜测压缩数据中的文件头。遇到截断的数据、未知边界或需要中央目录才能确定长度的数据描述符时停止扫描。只有 manifest 本身完整、CRC 校验通过，且当前工具支持其格式和索引契约，才继续核对文件长度及 SHA-256。

非法路径、大小写冲突、重复条目、已识别的符号链接、重叠区域、加密或不支持的压缩方式、资源超限会拒绝恢复。实际解压量也受限，不能通过伪造头部长度绕过。截断包中不再可见的中央目录属性无法重建；提取结果只包含普通文件字节，不创建符号链接或恢复文件权限。未登记文件不进入恢复工程，也不会递归解压附件。

SHA-256 和 CRC 用于发现损坏及索引不一致，不是数字签名，不证明来源或作者身份。manifest 不可解析、缺失或无法验证时，不提供基于猜测的工程恢复。较新格式和未知必需模块继续采用原包保留策略。

## 新工程的内容

恢复结果使用新的工程 UUID，名称追加“（恢复）”，revision 从 0 开始。源文件 ID 与相对路径尽量保留，以维持已验证文件之间的引用。

- 完整且受支持的配置模块按原声明恢复。缺失的活动入口设为 `null`，由正常校验报告缺项，不生成替代配置冒充原内容。
- 未知可选模块完整时仍按原模块只读保留；不完整模块的剩余文件作为 `recovery.quarantine` 只读文件保留。若运行依赖引用这些文件，校验会阻止运行导出。原模块声明为运行必需时，即使所有文件均缺失也保留阻断标记，避免恢复操作悄悄放宽运行要求；应从完整备份或对应适配器重新恢复该模块，当前不自动移除此标记。
- 编辑状态通过文件完整性检查后，逐项恢复合法且仍有对应文件的源码缓冲区，保留基础哈希以继续检查冲突。不会自动应用源码草稿。
- 人工确认全部重置。编辑状态原文作为只读附件保留；无法解析或无法恢复的缓冲区在报告中说明。
- `recovery-<新工程 UUID>/` 保存原 manifest、恢复报告和新编辑状态。报告包含原包 SHA-256、来源 UUID/快照、每个文件的结果及预期/实际哈希、未恢复模块与说明。

候选工程必须通过实际归档序列化和重新读取，才能供用户确认打开。恢复报告与隔离原文默认不进入运行包。配置解析、引用缺失和部署问题仍通过正常校验流程处理，恢复成功不代表配置可以运行。

## 保存与源文件保护

创建恢复工程前仍会确认工作区替换。取消检查、复制原包或关闭预览不会改变原工作区。原包复制使用输入字节，不经过重新打包。

损坏包检查在独立 Worker 中计算，进度按 ZIP 检查、文件哈希和候选工程重新归档阶段更新。取消操作会终止 Worker，保留原包与当前工作区，也不会把取消误报为新的损坏。原生写盘仍由桌面文件适配器负责，Worker 不持有文件授权。

桌面端创建恢复工程时保留来源文件授权作为受保护目标，不把它设为保存目标。首次保存需选择其他路径，后续另存为和副本操作继续排除此来源路径；常规保存只写新的工程文件。保护授权仅在当前工作会话有效，不写入归档或本机草稿。关闭应用或恢复本机缓存后没有原生文件授权，首次保存仍需选路径；用户应保留原始损坏包，手工选择路径时不要覆盖它。

网页端只生成新工程下载，不持有原文件覆盖权限。操作系统或浏览器下载界面的最终文件名由用户决定。

## 验证范围

核心测试覆盖 SHA-256 不一致、文件缺失、未登记条目、CRC 失败、中央目录截断、ENI 原字节、草稿恢复、模块隔离、人工确认重置、非法路径、符号链接与实际解压超限。浏览器测试覆盖原包字节复制、显式恢复、工作区替换和运行导出限制；GitHub Pages 子路径的断网测试也实际执行恢复与下载。Linux deb 中的真实程序已验证恢复后选择原包路径会被拒绝，原包字节不变，另选目标及后续保存正常。Windows 仍需在对应平台独立验收。

此机制不等同于任意 ZIP 修复工具：无法验证的 manifest、无法确定边界的文件数据、加密包、ZIP64、完整内容缺失、未知必要契约均不会被自动修复。文件系统断电、磁盘故障及所有外部归档器变体仍需独立验收。

恢复报告的原中文记录继续保留，新增可选消息模板供界面切换中英文显示；恢复文件路径、哈希及原始配置内容不参与翻译。归档失败原因、CRC/SHA-256 检查结果和恢复注意事项可在预览弹窗中即时切换语言，无需重复扫描或重新生成恢复工程。
