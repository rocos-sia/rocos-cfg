# 桌面离线版

最近一次内部版本的产物哈希、执行结果与边界见 [本地产物验证记录](BUILD-VERIFICATION.md)。

桌面壳使用 Tauri 2，内嵌与网页相同的生产构建。解析、编辑、校验、工程归档和运行配置导出仍使用 TypeScript 核心；Rust 只提供用户通过原生对话框选定的文件访问能力。桌面不注册 Service Worker，也不需要启动本机 HTTP 服务。

## 构建与启动

构建机需要 Node.js 22.12+、Rust stable 和对应平台开发依赖。开发环境准备参考 [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/)。以下命令在仓库根目录执行：

```sh
npm ci
npm run desktop:dev
npm run desktop:test:files
```

Linux 构建 deb：

```sh
npm run desktop:build -- --bundles deb
```

产物位于 `src-tauri/target/release/bundle/deb/`。安装前需准备发行版匹配的 GTK 3、WebKitGTK 4.1 及其依赖；deb 会声明运行依赖，但不会把 Linux 系统库全部内嵌。离线交付必须在联网准备阶段下载匹配目标系统的依赖包，或使用已经具备这些依赖的电脑。不要把一个 deb 文件称为适用于所有 Linux 电脑的完整离线安装介质。

Windows 构建 NSIS 安装程序：

```sh
npm run desktop:build -- --config src-tauri/tauri.windows.conf.json --bundles nsis
```

配置采用 `offlineInstaller`，在构建时获取并打入 WebView2 离线安装器，避免目标电脑在安装阶段现场下载 WebView。该配置及其安装器行为见 [Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/)。产物位于 `src-tauri/target/release/bundle/nsis/`。Windows 的实际构建、断网安装与运行仍需在 Windows 平台验收。

桌面构建按上述命令在本地执行；仓库仅保留 GitHub Pages 部署工作流。根目录 `VERSION` 为应用版本来源，提交与发布按仓库版本技能同步 npm、Cargo 和 Tauri 版本；界面由 Vite 在构建时注入同一版本。

## 工程文件操作

- **打开工程**：选择 `.rcproj`，分块读取并检查 SHA-256，再交给共用归档解析器。替换已有工作区前提示确认。未知必需模块或较新格式只进入摘要预览。
- **保存工程**：首次选择目标；后续保存至该路径。原生写入成功后才显示“已保存工程文件”。保存期间可以继续编辑，新修改不会被标记为已保存。
- **另存为**：要求选择不同于当前工程的路径；成功后切换后续保存目标。取消不改变原目标。
- **导出工程副本**：保留工程 UUID，生成新的快照 UUID，保持当前保存目标和保存状态。
- **复制为新工程**：在“校验与导出”中生成独立工程 UUID，名称追加“（副本）”，revision 从 0 开始。配置、资源、模块和未应用草稿完整保留；文件 ID 保持不变以维持包内引用。成功写出后可打开新工程独立维护，当前工作区、保存目标和保存状态不变；取消或失败也不影响原工程。
- **恢复损坏工程**：完整性检查失败时保留原包，显式检查并创建独立恢复工程。当前会话保留原包路径保护，首次保存、后续另存为和副本导出均不能选择受保护的原包；原包副本复制也要求其他路径。恢复工程需重新校验。详情见 [工程恢复](RECOVERY.md)。
- **导入资源目录**：读取选定目录下的普通文件并保留相对结构，再进入与网页相同的导入预览。拒绝符号链接、特殊文件以及超过大小、数量或深度限额的目录。

顶部“本机恢复草稿”按工作会话分别留存缓存，即使工程 UUID 相同也不会互相覆盖。可以恢复或清除指定旧草稿；恢复不附带原生文件授权，首次保存仍需选择路径。原缓存保留，且不会自动删除早期单槽位缓存。

Ctrl+S 保存，Ctrl+Shift+S 另存为。原生文件操作期间关闭应用会被阻止；存在未保存修改时提示确认。宿主绝对路径和文件访问令牌仅保留在当前会话，不写入 `.rcproj`。

归档压缩、打开校验、损坏包检查、跨文件校验和运行包生成使用包内的独立 Worker，计算阶段可继续编辑或取消。超过 256 KiB 的总线/URDF 视图解析也使用 Worker，切换解析输入或工作区时终止旧任务。Worker 只接收工程数据副本，不能访问原生文件令牌；终止计算不会覆盖目标文件。进度表示当前计算或文件传输阶段，不代表已经写盘。原生文件适配器完成替换后才更新保存状态。

## 覆盖、备份与失败恢复

原生文件服务返回稳定错误码、原中文 `message` 和可选显示模板；前端按当前语言渲染。操作系统错误、中文文件名与路径作为原始数据保留，不通过字符串替换猜测翻译。磁盘冲突弹窗的原因与差异表可即时切换语言，切换不更新文件授权、保存目标或哈希基线。写入完成后的目录同步警告同样携带模板，并保持“已写入但同步确认不足”的结果，不把成功替换误报为取消或未保存。

打开或上次保存时记录目标哈希。保存开始及替换前重新核对；检测到外部修改或删除时停止覆盖，允许比较磁盘工程的文件哈希与工作区，或另存为。查看差异不更新原保存基线。

文件分块写入目标同目录的临时文件，完成后同步并重新读取校验。替换已有文件前生成并验证上一版备份，命名为 `<原文件名>-backup-<唯一标识>.<扩展名>`。备份作为普通文件保留，由用户决定留存周期。取消、分块失败、内容不完整或校验失败时不替换原文件。

单次替换依赖操作系统和本地文件系统的重命名保证。哈希检查不是对其他进程的排他锁，检查到替换之间仍存在并发窗口；目录同步失败会明确提示文件已替换但持久化确认不足。强制杀进程可能留下 `.rocos-save-*` 或 `.rocos-backup-*` 临时文件，当前不会自动把它们当作有效工程恢复；应优先使用原工程、完成的备份或工作区草稿恢复。不要据此宣称已完成断电、磁盘故障或所有网络文件系统验收。

运行配置可以导出 ZIP，或选择“导出到新目录”。两者使用同一套跨文件校验、依赖收集和路径重写。目录模式在原生对话框选定的父目录下创建带随机后缀的独立目录，不合并或覆盖已有目录，也不改变工程保存目标。

新目录在写入期间属于暂存区，`ROCOS-EXPORT.json` 记录完整文件清单、大小、SHA-256 和 `incomplete` 状态。写入采用有序分块；全部文件重新读取校验后才将清单标记为 `complete` 并报告导出成功。该清单是交付校验记录，不属于主站或 APP 配置。路径冲突、保留清单文件名、非法/跨平台不兼容路径会拒绝写入。

取消或普通写入失败会清理本次暂存目录；清理失败会明确提示，原有目录不受影响。异常终止可能留下 `incomplete` 目录，不应当作有效运行配置；可依据清单检查后删除，再重新导出到另一个新目录。工具不自动接管、删除或覆盖历史暂存目录。多文件写入不是目录级原子替换；只有完成标记和文件哈希均有效的目录才是成功产物。当前采用新目录交付，所以不需要覆盖原运行目录及生成其备份。

## 原生验证

`npm run desktop:test:files` 不启动 GUI，验证真实临时文件上的覆盖备份、外部变化、取消、校验失败、分块顺序、并发写入、目录相对路径与授权边界。Windows 会跳过仅适用 Unix 的符号链接测试。

Linux 界面测试使用 WebKitWebDriver、tauri-driver 2.1.0、Xvfb、Openbox、xdotool、ImageMagick（`import` 窗口截图）和 Playwright Chromium。测试使用独立显示与临时用户数据目录，不操作日常桌面：

```sh
cargo install tauri-driver --version 2.1.0 --locked
npx playwright install chromium
PLAYWRIGHT_CHANNEL=chromium npm run desktop:test:ui
```

默认测试 `src-tauri/target/debug/rocos-configurator`，可通过 `ROCOS_DESKTOP_BINARY` 指定 release 或从 deb 中解出的程序。`WEBKIT_WEBDRIVER`、`TAURI_DRIVER`、`XVFB`、`WINDOW_MANAGER`、`XDOTOOL` 可指定工具路径。日志和截图写入 `test-results/desktop/`。测试会核对程序显示的版本与保存归档中的版本等于仓库 `VERSION`，避免使用旧二进制作为当前版本的验证证据。若测试依赖安装在独立 sysroot，还需设置相应 `LD_LIBRARY_PATH`、`XDG_DATA_DIRS` 和 `XDG_CONFIG_DIRS`，让 WebKitGTK、Openbox 主题及配置可被找到。

本地已在 Ubuntu 22.04 上构建 deb，并对包内解出的 release 程序通过以下测试：首次保存、覆盖备份字节一致、外部修改后拒绝覆盖、差异查看、另存为、原生目录导入、同 UUID 副本及新 UUID 工程复制均不改变原保存目标、桌面与浏览器工程往返、超过 256 KiB 的 URDF 后台解析、WebGL 视口初始化、取消未保存关闭提示，以及损坏包恢复、拒绝覆盖受保护原包、恢复工程另存与后续保存。原生文件与目录服务的 14 项测试也已通过，包含错误/警告序列化字段与中文路径保真。目录导出的原生界面测试覆盖取消父目录选择、清单完成状态及每项文件哈希、已有文件不变、与 ZIP 输出逐字节一致，以及导出后仍保存到原工程目标。界面测试会检查实际归档内容和备份字节，不只检查提示文案；基本 WebGL 视口测试不代表复杂模型全部渲染正确。

桌面验证仍不等于全项目验收：Windows 断网首次安装、Linux 缺依赖环境交付、磁盘满/崩溃恢复、全部复杂模型的 WebView 渲染需要继续覆盖。远端工作流尚未执行，不能把本地构建结果视为 Windows 或 CI 验收结果。
